 ## 1. 文档概要
 
 ### 1.1 文档目的
 
 本 PRD 旨在明确「网格交易系统」的产品范围、功能需求、技术约束与数据模型，为后续的 UI 设计、后端开发、前后端联调、测试验收提供统一参考基线。
 
 ### 1.2 适用范围
 
 本 PRD 覆盖系统的全部功能模块，包括：
 
 | 模块 | 说明 |
 |------|------|
 | 策略管理 | 内置行情策略 + 自定义网格参数 |
 | 标的管理 | 个股 / ETF / 基金与策略的绑定 |
 | 操作明细 | 策略 → 操作明细表的自动生成 |
 | 监控机器人 | 定时轮询价格，触发策略执行判断与消息推送 |
| 收益分析 | 理论收益率 vs 实际收益率计算与曲线展示 |
| 站内消息 | 策略重置到期提醒、买入/卖出触发操作提醒 |
| 用户界面 | 前端管理界面（Web） |

 ## 2. 产品定位与背景
 
 ### 2.1 产品背景
 
 用户在 ETF 和个股交易中采用网格交易策略，传统手工记录和计算效率低，且难以在不同行情形态（震荡向上、震荡、震荡向下）之间动态切换策略。需要一个集策略配置、自动监控、收益跟踪于一体的工具。
 
 ### 2.2 产品定位
 
 一款面向个人投资者的**轻量级网格交易管理平台**，覆盖从策略配置 → 自动监控 → 收益追踪的全链路，辅助用户做出网格交易的买入/卖出决策。
 
 ### 2.3 核心目标
 
 1. **降低策略管理复杂度** — 内置多种行情网格策略，开箱即用；
 2. **自动化监控** — 交易时段内自动轮询价格并比对策略条件；
 3. **收益透明可追溯** — 自动计算理论收益，并支持手工录入实际操作记录进行对比。

 |------|------|----------|
| 普通用户 | 使用网格交易功能的个人用户 | 管理自己的策略、标的、明细、监控与收益分析；查看公告 |

 ## 4. 功能需求
 
 ### 4.1 策略管理
 
 #### 4.1.1 内置行情策略模板
 
 | 策略模板 | 适用行情 | 描述 |
 |----------|----------|------|
 | 震荡向上策略 | 价格中枢缓慢上移 | 网格基准价跟随上升，不对称比偏向卖出方向 |
 | 震荡策略 | 价格在一定范围内反复 | 标准对称网格，买卖间距一致 |
 | 震荡向下策略 | 价格中枢缓慢下移 | 网格基准价跟随下移，不对称比偏向买入方向 |
 
 #### 4.1.2 自定义网格参数
 
 | 参数名 | 类型 | 必填 | 说明 |
 |--------|------|------|------|
 | 网格间距 | Float | 是 | 每个网格层之间的价格间距（百分比/绝对值可选） |
 | 网格层数 | Int | 是 | 以基准价为中心的网格层数（单侧或双侧） |
 | 不对称比 | Float | 否 | 买入层间距 / 卖出层间距的比例，默认 1.0（对称） |
 | 网格基准价 | Float | 是 | 网格中心的参考价格 |
 | 止损策略 | String | 否 | 价格跌破/涨破某层时的处理方式（全仓止损 / 暂停该层 / 无操作） |
 | 资金分配 | Enum | 是 | 等额均分 / 金字塔分配 / 自定义比例 |
 | 基准重置周期 | Int | 否 | 定期自动重新计算基准价的周期天数（如 14 天），默认不重置 |
 
 #### 4.1.3 基准价定期重置逻辑
 
 - 用户可对每个标的独立设置基准重置周期（单位：天）；
 - 到期后，系统根据该周期内的实际成交数据（成交均价或收盘价均值）自动更新网格基准价；
 - 重新计算后，网格层数及间距保持不变，但各层的挂单价格随之偏移；
 - 重置操作生成一条系统日志，记录重置前后的基准价变化。
 
 ### 4.2 标的管理
 
 #### 4.2.1 标的类型支持
 
 - 个股（A股）
 - ETF（交易型开放式指数基金）
 - 场外基金（仅每日盘后净值监控）
 
 #### 4.2.2 标的 → 策略绑定
 
 - 用户选择标的并为之分配一个已配置的策略（内置或自定义）；
 - 一个标的同一时间只能绑定一个策略；
 - 支持解绑与切换策略，切换后保留原策略的历史操作明细，新策略生成新明细。
 
 ### 4.3 操作明细表生成
 
 #### 4.3.1 自动生成逻辑
 
 - 每次策略配置完成或策略参数更新后，系统根据以下数据生成操作明细表：
   - 网格间距、层数、不对称比、基准价、资金分配方式；
   - 当前可用资金与持仓数量（用户录入或系统初始值）；
 - 明细表包含：
   - 各网格层的价格、买卖方向、数量、金额、累计资金占用；
   - 当前状态（等待买入 / 等待卖出 / 已触发 / 已失效）。
 
 ### 4.4 监控机器人
 
 #### 4.4.1 数据获取
 
 - 通过**行情数据接口**（如新浪 / 腾讯免费接口，或付费行情 API）获取实时或当日价格；
 - 个股 & ETF：交易时段内，每 **15 分钟** 轮询一次；
 - 场外基金：每个交易日 **收盘后**（15:00 后）获取最新净值。
 
 #### 4.4.2 条件判断
 
 - 将获取到的价格与当前生效策略各网格层的触发价格比对；
 - 若价格触及某一层的买入/卖出条件，生成一条**待执行提醒**。
 
 #### 4.4.3 消息推送
 
 | 渠道 | 到达方式 | 内容 |
 |------|----------|------|
 | 微信 | 企业微信机器人 / Server酱 | 标的名称、触发层、触发价格、买卖方向、建议数量 |
 | 钉钉 | 钉钉自定义机器人 Webhook | 同上 |
 
 > 支持用户配置推送开关，可分别启用/关闭各渠道。
 
 ### 4.5 收益分析
 
 #### 4.5.1 理论收益率（策略自动计算）
 
 - 以策略参数为输入，在预设的价格路径上模拟各网格层的触发过程；
 - 输出：
   - 单次买卖的理论收益率；
   - 累计收益率曲线（随时间/步数）；
   - 年化收益率估算。
 
 #### 4.5.2 实际收益率（手工录入）
 
 - 用户可手工录入每笔实际操作记录，字段包括：
   - 操作时间、标的、买卖方向、成交价格、成交数量、手续费；
- 系统根据录入记录绘制实际收益率曲线；
- 支持与理论收益率曲线叠加对比。

### 4.6 系统管理模块

系统管理模块仅管理员可用，包含四个子模块：

#### 4.6.1 用户管理

- 管理员可查看全部用户列表：账号、手机号、角色、状态、账号有效期、创建时间；
- 支持新增用户、编辑用户（重置有效期、调整角色、启用/停用）；
- 普通用户不可访问用户管理功能。

#### 4.6.2 角色管理

- 系统预置两个角色：**管理员** 与 **普通用户**；
- 角色包含 **功能权限** 与 **数据权限**：
  - 功能权限：控制该角色可访问的功能模块（如系统管理、策略管理、标的管理、监控、收益分析、站内消息）；
  - 数据权限：`本人`（只能看到自己的数据）或 `全部`（可查看全部用户数据）；
- 预置规则：
  - 管理员：全部功能权限 + 数据权限 = 全部；
  - 普通用户：不含系统管理功能权限 + 数据权限 = 本人；
- 支持管理员自定义新角色并配置权限。

#### 4.6.3 系统参数配置

- 参数以键值对形式存储（param_key / param_value）；
- 预置参数：`账号有效期(天)` = `5`；
- 账号有效期参数用于注册时给新用户计算账号过期时间；
- 支持后续动态增加参数。

#### 4.6.4 公告配置

- 管理员可发布、编辑、停用公告；
- 公告字段：标题、内容、状态（启用/停用）、发布时间；
- 启用的公告对所有登录用户展示。

### 4.7 登录注册

#### 4.7.1 注册

- 注册必填：账号、密码、手机号；
- 注册成功后默认角色为 **普通用户**；
- 账号有效期 = 当前日期 + 系统参数「账号有效期(天)」；
- 手机号需唯一。

#### 4.7.2 登录

- 登录凭证：账号 + 密码；
- 登录成功后返回用户信息与 Token；
- 前端显示当前登录 **账号** 与 **账号有效期**；
- 账号过期或停用后禁止登录。

### 4.8 公告展示

- 登录后首页/侧边栏展示最新启用公告；
- 公告按发布时间倒序展示标题和内容摘要。

## 5. 非功能需求
 
 | 类别 | 需求描述 | 验收标准 |
 |------|----------|----------|
 | 性能 | 监控轮询间隔 ≤ 15 分钟（个股/ETF） | 从定时器触发到推送完成 ≤ 30s |
 | 可用性 | Web 界面核心操作在 2 次点击内可达 | 用户路径评审通过 |
 | 数据准确性 | 网格基准价重置计算、收益率计算准确 | 单元测试覆盖核心计算逻辑 |

 | 存储 | MySQL 数据库，本地部署 | localhost:3306 |

 ### 6.2 技术选型建议
 
 | 层级 | 技术选型 | 说明 |
 |------|----------|------|
 | 前端 | Vue 3 + Element Plus / React + Ant Design | 视团队熟悉度选择 |

 - 一期不考虑云端部署或 Docker Compose 编排（可选后期优化）。

 ## 8. 数据流说明
 
 ### 8.1 核心流程一：配置策略 → 生成明细
 
 1. 用户选择模板或新建自定义策略；
 2. 填写参数（间距、层数、不对称比、基准价、止损等）；
 3. 前端校验 → 提交后端 → 写入 `strategy_instance`；
 4. 后端调用明细生成引擎，根据资金分配规则计算各层，写入 `grid_layer`；
 5. 前端刷新展示明细表。
 
 ### 8.2 核心流程二：监控机器人 → 推送
 
 1. 调度器每 15 分钟（个股/ETF）触发一次；
 2. 从 `strategy_instance` 加载所有状态为 active 的策略；
 3. 通过行情接口获取对应标的最新价格；
 4. 逐个比对 `grid_layer` 中待触发层的 trigger_price；
 5. 若触发 → 新增 `operation_log`（理论类型） → 调用推送模块发消息；
 6. 若未触发 → 记录价格快照到 `price_snapshot` 后结束。
 
 ### 8.3 核心流程三：基准价重置
 
1. 每日收市后，调度器检查所有设置了 `reset_cycle_days` 的策略；
2. 距离 `last_reset_time` 已过周期的策略进入重置流程；
3. 获取该周期内的成交均价或收盘价均值，作为新基准价；
4. 重新生成 `grid_layer` 并记录 `reset_log` → 创建站内重置提醒消息。

### 8.4 核心流程四：用户注册 / 登录 / 数据隔离

1. 用户填写账号、密码、手机号注册 → 后端创建 `user` 记录（角色=普通用户，有效期=当前日期+系统参数账号有效期）；
2. 用户登录 → 校验账号密码 → 校验账号状态与有效期 → 签发 JWT Token → 返回用户信息；
3. 前端将 Token 存入 localStorage，并在所有 API 请求头携带 `Authorization: Bearer <token>`；
4. 后端从 Token 解析当前用户，业务查询自动追加 `user_id = 当前用户` 条件（本人数据权限）；
5. 管理员（数据权限=全部）可跨用户查询，前端系统管理模块可查看全部用户数据。

### 8.5 核心流程五：公告发布与展示

1. 管理员在系统管理→公告配置中发布公告；
2. 公告状态为启用时对所有登录用户可见；
3. 登录后前端请求公告接口，展示最新启用公告。

 ## 9. 风险与约束
 
 | 风险项 | 影响 | 缓解措施 |
 |--------|------|----------|
 | 行情接口不稳定或免费接口关闭 | 监控中断 | 预留多种行情源切换机制 |
 | 用户本地部署环境差异（Python / Node 版本） | 启动失败 | 提供 requirements.txt / package.json 版本锁定 |
 | 数据库密码硬编码 | 安全风险 | 采用环境变量 `.env` 配置文件 |
 | 交易时段判断错误 | 盘后基金净值推送时机错误 | 内置 A 股交易日历，支持手动修正 |
 | 15 分钟轮询间隔可能错过盘中短暂价格 | 触发延迟 | 提供可配置的轮询频率（5/10/15 分钟） |
